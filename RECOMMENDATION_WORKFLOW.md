# Навык: сохранить игровую рекомендацию

## Назначение
По явной команде пользователя «сохрани рекомендацию», «добавь игру в архив» или «посоветуй и сохрани» обновить публичный каталог Personal Game Archive в GitHub.

## Репозиторий
- `nulliam0/personal-game-archive`
- Данные: `games.json`
- Отображение: `index.html`
- Контекст: `PROJECT_CONTEXT.md`
- Сайт: https://nulliam0.github.io/personal-game-archive/

## Обязательная проверка
1. Определить точное название игры и целевую платформу (Switch, 3DS, DS, PC, Android).
2. Подтвердить русский язык **именно на этой платформе**: официальный, совместимый фанатский или машинный перевод. Не считать существование ПК-перевода доказательством перевода Switch.
3. Найти страницу автора/проекта перевода, указать известные ограничения и совместимость. Если перевод не подтверждён — не добавлять как готовую рекомендацию; можно оставить в списке проверки только по отдельной просьбе пользователя.
4. Написать короткое индивидуальное объяснение, почему игра подходит пользователю: MGS, Persona, Yakuza, FFIX, NieR, Death Stranding, Animal Crossing: New Leaf, авторские игры, музыка, персонажи, абсурд, личный портативный формат.
5. Подобрать достоверную вертикальную обложку игры (желательно формат 2:3), проверить, что изображение соответствует нужной игре и доступно по ссылке. Не угадывать адреса. Использовать локальный файл `covers/<id>.<расширение>` после успешного кеширования, а исходный URL сохранять отдельно в `coverSourceUrl`. Если источник не проверен, явно оставить задачу обложки незавершённой.
6. Прочитать текущий `games.json`, найти возможные дубликаты по названию и платформе. Для обновления существующей записи сохранить её `id`, чтобы не сбросить локальные статусы и заметки.
7. Добавить/обновить запись по действующей схеме: `id`, `name`, `platform`, `language` (`official` / `fan` / `check`), `description`, `translationUrl`, `coverUrl` и при необходимости `coverSourceUrl`. Не менять имена существующих полей.
8. Проверить валидность JSON и выполнить запись через GitHub-коннектор. Не редактировать `index.html`, если схема и дизайн не требуют изменений.
9. Для обложек использовать `.github/workflows/cache-covers.yml`: после изменения `games.json` workflow должен попытаться скачать и проверить изображение, сохранить в `covers/` и записать результат в `cover-report.json`. Проверить статус GitHub Actions и отчёт. Не считать обложку добавленной, если она осталась внешней ссылкой, не прошла проверку или workflow завершился ошибкой. При сбое искать другой достоверный источник.
10. Проверить, что `coverUrl` ссылается на реально существующий файл `covers/` после кеширования; не менять идентификатор игры, чтобы не потерять статусы и заметки пользователя.
11. Сообщить пользователю, что сохранено в репозитории, со ссылкой на коммит или файл. Не утверждать, что GitHub Pages уже обновился, пока публикация не проверена.

## Правила безопасности и приватности
- Не добавлять приватные истории пользователя в публичный репозиторий.
- Не включать ссылки на пиратские раздачи игр; допустимы ссылки на страницы русификаторов, homebrew и официальные магазины.
- Существующие личные отметки и заметки сохраняются в браузере; сайт их автоматически не синхронизирует.
- Ничего не публиковать автоматически при обычном обсуждении игры без просьбы пользователя.

## Команды
- «Сохрани [игру] в архив» — проверить и записать.
- «Посоветуй 5 игр на Switch и сохрани подходящие» — сначала исследовать, затем записать прошедшие проверку.
- «Обнови русификатор для [игры]» — обновить существующую запись, сохранив ID.
- «Проверь игры без подтверждённого русского» — исследование без автоматической публикации, если не было команды сохранить.
